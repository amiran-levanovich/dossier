# Quick Reference — the 10-rule floor

Re-read this when context is tight, after a compaction, or whenever unsure. It is the distilled floor of `job_workflow.md`, not a replacement — follow the full kernel when you can.

1. **Session start:** read `goals.md`, `tracker.csv` and `master_cv_signoff.md` before responding. Never ask what a file answers. All live in the current working directory — no `story_bank.md` there means a fresh folder: route to `job-intake`, never search elsewhere.
2. **Order holds:** no `job-apply` without a **signed-off** `master_cv.md` and current goals; a stale sign-off (hash no longer matching) counts as unsigned. Route to `job-intake` / `job-goals` first.
3. **Resume, don't re-ask:** `interview_progress.md` is the save-game and seeded agenda — continue from it, never re-interview recorded areas.
4. **A CV bullet is a hypothesis:** seeded claims sit on the agenda until the gauntlet confirms them; only interrogated material enters the bank, and only the bank backs the exemplar.
5. **Gate before writing:** the ATS keyword check (`standards/ats_rules.md`) first — it is free and the gate cites it — then the fit gate (`core/fit_check.md`: liveness, constraints kill-switch, evidence-cited score, legitimacy tier; the user's override wins and is recorded). Both before building anything.
6. **Exact names, never equivalency language:** "X-equivalent" and "similar to X" are invisible to ATS. Name the tool or omit it.
7. **The CV is trimmed, never written:** every line comes byte-verbatim from the signed-off `master_cv.md`, and assembly proves it. A claim it lacks is a one-off slot or a promotion — never a reworded slot.
8. **The gate is the door, and runs once:** it judges the letter's fact containment — the facts *and* their attribution — against the assembled CV, plus any one-off slot; all else inherits the exemplar's verdict. An invented fact is removed, a merged one split, a promotion candidate the user's call. Never present with open BLOCKER/MAJOR findings.
9. **Never fabricate unprompted.** The writer proposes no one-off of its own. If the *user* directs an unsupported claim: warn once, confirm, get details, then declare it as a one-off slot the gate judges at full rigor.
10. **Close the loop:** tracker current with dated `next_action`s, application folder complete, new facts written back to `story_bank.md` (plus a lesson line if a post-mortem or debrief ran) — before the session ends.

## When lost

Re-read in this order, stopping as soon as you're oriented: **this file → `interview_progress.md` + `master_cv_signoff.md` → `core/job_workflow.md`**. Still unsure → ask the user. Asking is cheap; guessing wrong is not.
